# 浏览器面板的列归属

状态：两个版本当前一致。

2026-09-17：桌面浏览器面板把右侧轨道画成自己的一层，轨道的席位仍归官方右侧边栏；当侧边栏抬起自己的面板时，浏览器面板让出该列。

[English](2026-09-17-browser-column-ownership.md) | 中文

## 边界

右侧轨道只有一个席位 `rightbar`，由官方右侧边栏注册。桌面浏览器面板不再与它竞争：面板注册 `desktop.browser.column`，这是 frame 画在同一轨道之上的独立一层。于是两个表面同时存在——面板打开期间侧边栏的席位保持挂载，它的会话表面继续回答 `sidebarRight`，打开文件与预览资源的命令不再因为缺少已挂载表面而失败。空图层不接收指针事件，因此下面的侧边栏仍能收到自己的点击。

## 列归属

frame 的 layout 服务分别记录两方的呈现：侧边栏通过 `openRightbar`/`closeRightbar` 报告自己的面板，浏览器面板通过 `showBrowserColumn`/`hideBrowserColumn` 声明占用。面板的有效占用在存续期间优先于侧边栏的报告——用户看到的是面板——frame 按当时生效的那一方摆放轨道。当侧边栏的面板由隐藏变为显示而浏览器仍占用该列时，frame 把这件事作为 `sidebarTakeover` 交给面板图层；该会话的面板随即关闭自身并保留标签，该列连同其中已经就位的内容回到侧边栏。标记随被打断的那次占用一起清除，因此在一个已经显示的侧边栏之上重新打开面板不会被立即关闭。

## 结果

释放面板只撤销面板自己的占用：正在显示的侧边栏保留自己的轨道，不会被面板退出时关掉。根作用域只有这一层，它跟随屏幕上的会话，因此多个会话可以各自保持打开的面板，而不必注册互相竞争的 occupant。未安装官方侧边栏的桌面端不报告任何呈现，面板于是独自使用该列。
